# CTF 多重base エンコード問題 まとめ

## 問題の概要

`Alpaca{...}` というフラグを、base16 / base32 / base64 のどれかで **20回ランダムに多重エンコード**した文字列（`output.txt`）が与えられる。これを復号してフラグを取り戻すのが目的。

## 出題スクリプト

```python
import os
import random
from base64 import b16encode, b32encode, b64encode

flag = os.environ.get("FLAG", "Alpaca{**** REDACTED ****}").encode()

for i in range(20):
    base = random.choice([16, 32, 64])   # 毎回1つだけ選ぶ
    if base == 16:
        flag = b16encode(flag)
    elif base == 32:
        flag = b32encode(flag)
    elif base == 64:
        flag = b64encode(flag)

flag = flag.decode()
print(flag)
```

### ポイント

- 20回ループし、**各回で 16 / 32 / 64 のうち1つだけ**を選んでエンコード（3種類全部を毎回かけるわけではない）。
- どれを使ったかは **記録・出力されない** → 解く側は「各層の種類（＝順番）」を知らない。

## なぜ解けるか

base16 / base32 / base64 は **鍵のない可逆変換**（暗号ではない）。情報が失われないので、**かけた順の逆で剥がせば必ず元に戻る**。わからないのは「順番」だけ。

```
かけた順:  flag → [16] → [64] → [32]     （外側が最後の32）
剥がす順:        32 → 64 → 16 → flag      （外側から逆に）
```

もしどこかの層が鍵付きの本物の暗号だったら、鍵なしでは解けなかった。

## 復号の考え方

外側の層から順に剥がす。各層の種類は総当たりで特定する。

- 各段で `b64decode → b32decode → b16decode` を試す。
- **エラー**なら `except` で次の方式へ。
- **エラーは出ないが中身がゴミ**（例：base32 の出力が偶然 base64 として通る）の場合は深く潜り、行き詰まって `None` が返る → `if r:` が False になり次の方式へ戻る（**深さ優先探索＋バックトラック**）。
- `depth` カウンタで20回剥がしたかを管理し、底で `Alpaca{` 始まりかを確認して確定。

### 文字種による見分け方（参考）

| エンコード | 出力に現れる文字 | 見分けの手がかり |
|---|---|---|
| base16 | `0-9A-F` | `0,1,8,9` が出るのは16だけ（32の数字は `2-7`） |
| base32 | `A-Z2-7` `=` | 大文字 `G-Z` を含むが小文字なし |
| base64 | `A-Za-z0-9+/` `=` | 小文字や `+` `/` が出るのは64だけ |

※ ただし判定が曖昧なケースがあるため、確実なのは総当たり＋バックトラック。

## 完成した復号コード

```python
from base64 import b16decode, b32decode, b64decode

def solve(s, depth=0):
    b = s.encode() if isinstance(s, str) else s
    if depth == 20:
        try:
            t = b.decode()
            if t.startswith("Alpaca{"):
                return t
        except UnicodeDecodeError:
            pass
        return None
    for dec in (b64decode, b32decode, b16decode):
        try:
            r = solve(dec(b), depth=depth + 1)   # depth を正しく積む
            if r:
                return r
        except Exception:
            pass
    return None

with open('output.txt') as f:
    encode = f.read().strip()       # 中身を読む＆末尾の改行を除去
print(solve(encode))
```

## 再帰処理のデータの流れ

- **下り**：bytes を1層ずつ剥がしながら `depth` を 0 → 1 → … → 20 と増やす。
- **底（`depth == 20`）**：`Alpaca{` 始まりかで正解判定。
- **上り**：見つけた文字列（正解）または `None`（ハズレ）を呼び出し元へ伝播。
- **バックトラック**：間違った方式で深く潜って `None` が返ると、`if r:` が False になり for ループが次の方式へ戻ってやり直す。

## ハマりどころ（バグ）

- `depth= + 1` は単項プラスの `1` になり depth が積まれない → 正しくは `depth=depth + 1`。
- `open('output.txt','r')` はファイルオブジェクトで中身ではない → `.read().strip()` が必要。
- base16 は大文字前提。不安なら `b16decode(b, casefold=True)`。
- `depth == 20` で不一致のときは `return None` で打ち切る（`pass` で下の for に落とすと20層より深く潜り続けてしまう）。

## 一言まとめ

**多重エンコード＝難読化であって暗号化ではない。可逆なので、順番を総当たりで剥がせば必ず戻せる**、という問題。
